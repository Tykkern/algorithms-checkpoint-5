# Контрольная точка 5: сортировки и бинарный поиск

Практикум по алгоритмам. Сортировка слиянием, быстрая сортировка, бинарный поиск
и поиск границ диапазона на Java. Встроенные `Arrays.sort` и `Arrays.binarySearch`
используются только в самопроверке и тестах, в самих алгоритмах их нет.

| Часть | Методы | Класс | Время | Доп. память |
|---|---|---|---|---|
| 1 | `mergeSort`, `merge` | `MergeSort` | O(n log n) всегда | O(n) |
| 2 | `quickSort`, `partition` | `QuickSort` | O(n log n) в среднем | O(log n) стек |
| 3 | `binarySearch` | `Search` | O(log n) | O(1) |
| 4 | `lowerBound`, `upperBound` | `Search` | O(log n) | O(1) |

## Запуск

Нужен JDK 17 или новее, Gradle скачается сам через wrapper.

```
gradlew test       # тесты
gradlew run -q     # пример и самопроверка
```

`gradlew run` сортирует небольшой массив обеими сортировками и `Arrays.sort`,
показывает поиск и границы рядом с `Arrays.binarySearch` и подсчётом вручную,
затем прогоняет 2000 случайных массивов и печатает число расхождений.

На Windows проект лучше держать в папке без кириллицы в пути. Иначе Gradle
не находит тестовые классы (`ClassNotFoundException`), хотя они скомпилированы.

## 1. Сортировка слиянием

`mergeSort(arr, left, right)` делит диапазон пополам, сортирует половины
рекурсивно и сливает их методом `merge(arr, left, mid, right)`. Слияние идёт
двумя индексами, по одному на половину, и каждый раз забирает меньший элемент
во временный массив. Когда одна половина кончилась, хвост второй дописывается
без сравнений, и результат копируется обратно.

Устойчивость обеспечивает условие `arr[i] <= arr[j]`: при равенстве берётся
элемент из левой половины, то есть тот, что стоял раньше. Со строгим `<`
равные элементы из правой половины обгоняли бы левые.

Глубина рекурсии log n, на каждом уровне слияния проходят все n элементов,
итого O(n log n) на любых входных данных.

## 2. Быстрая сортировка

### Выбор опорного элемента

Выбран **случайный опорный элемент**. Перед разбиением `partition` берёт
случайный индекс из `[low, high]` и ставит этот элемент в начало диапазона.

Если опорным всегда брать последний элемент, на отсортированном массиве он
каждый раз оказывается максимумом. Разбиение отрезает от диапазона один
элемент, глубина рекурсии становится n, а сравнений около n²/2. Причина в том,
что худший вход заранее известен и встречается на практике.

При случайном выборе плохой опорный выпадает только случайно, и зависимости от
порядка входных данных нет. Отсортированный, обратный и любой другой массив
сортируются в среднем за O(n log n). Чтобы получить O(n²), неудачный опорный
должен выпадать раз за разом, а вероятность этого на больших n ничтожна.

Медиана из трёх (первый, средний, последний) тоже спасает отсортированные
массивы, но под неё можно специально подобрать вход, на котором она
деградирует. Случайный выбор так не обмануть, потому что он не зависит от
расположения элементов.

### Разбиение

Используется схема Хоара. Два индекса идут навстречу: левый останавливается на
элементе не меньше опорного, правый на элементе не больше, и эти элементы
меняются местами. Когда индексы встретились, `partition` возвращает границу
`split`. Слева от неё (`[low, split]`) всё не больше опорного, справа
(`[split + 1, high]`) всё не меньше. Обе части непустые.

Схема Хоара выбрана из-за повторов. В схеме Ломуто элементы, равные опорному,
все уходят в одну часть. Массив из одинаковых чисел тогда делится как 1 и n - 1
даже при случайном опорном, и снова получается O(n²). У Хоара оба индекса
останавливаются на равных опорному, поэтому такие элементы расходятся по обеим
частям, и массив из одинаковых чисел делится пополам.

### Глубина рекурсии

`quickSort` рекурсивно вызывается только для меньшей из двух частей, а большая
обрабатывается следующим проходом цикла. Меньшая часть не больше половины
диапазона, поэтому стек не глубже log n при любых опорных элементах.

## 3. Бинарный поиск

Поиск на отрезке `[left, right]`. Середина сравнивается с искомым, и отрезок
сужается до половины, где искомое ещё может быть. Если отрезок опустел,
элемента нет и ответ `-1`. При повторах возвращается индекс одного из равных
элементов, как и у `Arrays.binarySearch`.

Середина считается как `left + (right - left) / 2`. Формула `(left + right) / 2`
переполняет int, когда сумма границ больше `Integer.MAX_VALUE`, то есть на
массивах длиннее примерно миллиарда элементов. Разность границ не превышает
длину массива, поэтому первая формула переполниться не может.

## 4. Границы диапазона

Оба метода ищут на полуинтервале `[left, right)` от `0` до `length`. Всё левее
`left` уже точно «слишком маленькое», всё начиная с `right` уже точно
подходит. Когда границы сходятся, это и есть ответ.

- `lowerBound` - первый индекс с `arr[i] >= target`: сдвигаем `left`, пока
  `arr[mid] < target`.
- `upperBound` - первый индекс с `arr[i] > target`: сдвигаем `left`, пока
  `arr[mid] <= target`.

Если все элементы меньше `target`, оба метода возвращают `length`. Разница
`upperBound - lowerBound` равна числу вхождений `target`, а `lowerBound`
одновременно даёт позицию, куда `target` можно вставить без нарушения порядка.

## Тесты

- обе сортировки сравниваются с `Arrays.sort` на копиях тех же массивов:
  3000 случайных, а также пустой, из одного элемента, с повторами,
  отсортированный, обратный и с крайними значениями int;
- быстрая сортировка на миллионе элементов: отсортированные, обратные,
  одинаковые, с тремя различными значениями и случайные, таймаут 5 секунд;
- `partition` проверяется отдельно: обе части непустые, слева всё не больше,
  чем справа, элементы не теряются;
- бинарный поиск сверяется с `Arrays.binarySearch`, границы с подсчётом
  вхождений вручную и с определением на каждом индексе;
- самопроверка из `Main` проходит без расхождений.
